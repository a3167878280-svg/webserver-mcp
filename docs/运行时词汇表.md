# 运行时词汇表

本词汇表按顺序追加。每个词条优先回答四件事：它是什么、何时出现、保存什么数据、与哪些词有关。

## 使用约定

- 后续讲次只追加首次出现的新词；已定义术语只链接回本页或在正文中简短复用。
- “运行时”指服务器进程启动后，存在于内存、连接或持久化状态中的对象和数据，不等同于磁盘上的源代码。
- 词条描述项目当前的学习模型；实现细节与代码位置放到后续的代码验证阶段再补充。

## 第 1 讲：项目地图与启动前状态

### 运行时配置

从配置文件读取并留存在内存中的启动决策集合。它决定服务模式、端口、插件目录、日志策略和默认 LLM 连接信息。服务器启动后，多数基础组件都依据它完成初始化。

关联词：配置文件、服务模式、插件目录、默认 LLM 连接信息。

### 配置文件

启动前保存在磁盘上的文本配置，是运行时配置的输入。读取失败或格式错误时，系统可使用默认值继续启动，因此实际运行配置未必与文件内容完全一致。

关联词：运行时配置、默认值。

### 默认值

当配置缺失、无法读取或部分字段未提供时使用的预设运行参数。它保证服务在不完整配置下仍可尝试启动，但可能导致服务模式、端口或外部连接目标与预期不符。

关联词：配置文件、运行时配置。

### 服务模式

服务器对外接收和发送消息的工作形态。本项目有 stdio 模式和 HTTP 模式：前者通过标准输入输出通信，后者通过 HTTP 接收请求并可用 SSE 推送消息。

关联词：stdio、HTTP、传输通道、SSE。

### stdio

一种本地进程间通信方式。客户端通过服务器进程的标准输入发送协议消息，通过标准输出接收响应。消息需要明确长度边界，避免连续字节流中的多条消息混淆。

关联词：服务模式、传输通道、长度边界、协议消息。

### HTTP

一种网络请求协议。在本项目的 HTTP 模式中，客户端用 HTTP 请求提交数据；服务器还可借助 SSE 向客户端异步推送协议响应或聊天事件。

关联词：服务模式、SSE、会话 ID、传输通道。

### SSE

Server-Sent Events 的简称，是服务器到客户端的持续单向事件流。本项目用它把 HTTP 请求处理后的异步结果，以及聊天过程中的文本增量和工具状态，推送给浏览器。

关联词：HTTP、会话 ID、流式事件。

### 传输通道

外部客户端与服务器之间传递消息的入口和出口。它负责把字节、HTTP body 等外部形式交给上层，并把上层生成的结果送回客户端；它不负责决定调用哪个能力。

关联词：stdio、HTTP、SSE、协议消息。

### 插件目录

配置指定的磁盘位置，服务器启动时从这里发现可装载的插件库。目录中有插件库只是候选状态，只有成功装载并登记后，其中的能力才对客户端可见。

关联词：插件库、插件实例、能力注册表。

### 插件库

可被服务器在运行时装入的独立二进制模块。它包含一个或多个实际能力的实现，以及用于创建和销毁插件实例的约定入口。

关联词：插件目录、插件实例、动态装载。

### 动态装载

服务器启动或运行时，把独立插件库映射进当前进程并创建其插件实例的过程。它让主程序无需在编译时固定每一种业务能力。

关联词：插件库、插件实例、生命周期。

### 插件实例

插件库被装载后，在服务器内存中产生的可交互对象。它申报自己提供哪些能力，并在后续请求到来时执行具体业务。实例通常从服务器启动后存活到关闭或卸载。

关联词：插件库、能力定义、生命周期、能力注册表。

### 能力

服务器向客户端公开的可发现单元。本项目的能力分为 Tool、Resource、Prompt 三类；每项能力都有唯一的查找标识和描述信息，并由某个插件实例拥有。

关联词：Tool、Resource、Prompt、能力定义、能力注册表。

### 能力定义

启动登记阶段保存的描述性数据，而非实际业务结果。它包括能力的名称或 URI、用途说明、参数结构或内容类型等，使客户端和 LLM 知道“能做什么、该怎样请求”。

关联词：能力、工具结果、资源 URI、提示模板。

### Tool

可执行的能力类型。调用者提供工具名和参数，所属插件执行动作并返回结果。适合查询、读取、命令执行、代码审查等需要实际操作的场景。

关联词：工具名、工具参数、工具结果、插件实例。

### Resource

可读取的数据类型。服务器先公开资源 URI 和描述，客户端再按 URI 请求内容。它强调“可浏览的数据”，而不是一次带参数的执行动作。

关联词：资源 URI、资源内容、插件实例。

### Prompt

可复用的对话模板类型。用户选择模板并提供所需参数后，服务器返回预先组织好的对话消息；它本身不等于工具执行。

关联词：提示模板名、模板参数、消息。

### 能力注册表

服务器内存中的能力索引。它记录“工具名、资源 URI 或提示模板名”分别属于哪个插件实例，以及相应的能力定义；请求到来时据此定位执行者或提供目录。

关联词：能力索引、插件实例、工具名、资源 URI、提示模板名。

### 能力索引

能力注册表内部按唯一标识建立的映射关系。它不是能力的业务执行逻辑，也不保存每次调用的结果；其作用是让后续请求能稳定、快速地找到能力所有者。

关联词：能力注册表、工具名、资源 URI、提示模板名、冲突。

### 工具名

标识某项 Tool 的唯一名称。工具调用使用它在能力注册表中查找所属插件；同名声明发生冲突时，后注册的声明不会覆盖已登记项。

关联词：Tool、能力索引、冲突。

### 资源 URI

标识某项 Resource 的唯一地址形式。客户端先从资源目录发现它，再用 URI 请求对应内容。

关联词：Resource、能力索引、资源内容、冲突。

### 提示模板名

标识某项 Prompt 的唯一名称。用户或客户端以它选择一个对话模板，再提供该模板所需的参数。

关联词：Prompt、能力索引、模板参数、冲突。

### 冲突

两个插件声明相同工具名、资源 URI 或提示模板名的情况。为了保证一次请求有唯一去向，运行时会保留先成功登记的能力，忽略后来的同名或同 URI 声明。

关联词：能力索引、工具名、资源 URI、提示模板名。

### 生命周期

一个运行时对象从创建、使用到销毁的时间范围。插件实例的典型生命周期是：动态装载后创建，登记能力，处理多次请求，停止时注销能力并销毁。

关联词：动态装载、插件实例、能力注册表、注销。

### 注销

在销毁插件实例前，先从能力注册表删除其所有能力索引的过程。这样后续请求不会查到已经失效的插件实例。

关联词：生命周期、能力注册表、插件实例。

### 日志系统

用于记录服务器启动、插件装载、请求处理和异常信息的基础运行设施。它帮助观察实际运行状态，但不参与协议路由或业务执行决策。

关联词：运行时配置、基础服务。

### 停止控制

服务器接收到退出信号后，用于结束等待、停止传输通道并清理长期对象的运行机制。它保证服务不会在退出时继续接受新工作。

关联词：生命周期、传输通道、注销。

### 对话管理器

管理聊天会话及其历史的长期运行对象。它可以在服务器启动时存在，但只有恢复旧会话或收到新的聊天活动后，才会持有具体会话历史。

关联词：会话、会话历史、会话 ID、聊天路径。

### 会话

一段可持续关联的聊天或连接上下文。它将多条相关消息组织在一起；HTTP/SSE 连接和聊天历史都可能使用会话概念，但用途和生命周期需要在后续讲次分别辨析。

关联词：会话 ID、会话历史、SSE。

### 会话历史

属于某个聊天会话的消息记录，可包含用户消息、助手回复和工具结果。它为 LLM 在多轮对话中理解上下文提供数据。

关联词：会话、对话管理器、消息、LLM。

### 会话 ID

标识一段会话的唯一值。在 HTTP/SSE 场景中，它可把请求与服务器向对应客户端推送的事件关联起来；在聊天场景中，它也可用于定位要恢复和保存的历史。

关联词：会话、SSE、会话历史、请求 ID。

### LLM

Large Language Model 的简称，即大语言模型。聊天路径会向它提供用户消息、历史和可用工具定义；它返回文本，或提出工具调用意图。

关联词：默认 LLM 连接信息、消息、Tool、工具调用意图。

### 默认 LLM 连接信息

运行时配置中用于连接模型服务的默认地址和模型标识。聊天请求没有单独覆盖这些信息时，系统使用它们与 LLM 建立通信。

关联词：运行时配置、LLM、聊天路径。

### 请求 ID

关联一条协议请求与其协议响应的标识。它的作用范围通常是一轮 MCP 往返，不应与用于持续连接或聊天历史的会话 ID 混为一谈。

关联词：协议请求、协议响应、会话 ID。

### 协议消息

客户端与服务器按共同协议交换的结构化内容。在传输层之外，它通常表现为 JSON 文本；后续会被解析为协议请求或协议响应。

关联词：传输通道、协议请求、协议响应、JSON。

### JSON

一种文本化结构数据格式。本项目使用它承载协议消息、配置内容和部分持久化数据；它能表达对象、数组、字符串、数字和布尔值等结构。

关联词：协议消息、配置文件、协议请求、协议响应。

### 协议请求

客户端发给服务器的结构化意图，至少携带要执行的动作、相关参数，以及通常用于匹配响应的请求 ID。第 2 讲会继续解释它如何被解析和路由。

关联词：请求 ID、协议响应、方法、参数。

### 协议响应

服务器对一条协议请求给出的结构化结果，包含成功结果或错误信息，并回显请求 ID 以便客户端匹配。第 2 讲会继续解释其生成过程。

关联词：请求 ID、协议请求、结果、错误。

### 参数

随请求传递的结构化输入数据。不同协议动作和不同 Tool/Prompt 需要的参数形状不同；能力定义会告诉调用者可接受哪些参数。

关联词：协议请求、Tool、Prompt、能力定义。

### 工具结果

某次 Tool 执行完成后产生的统一业务结果，通常含可展示的内容和成功或失败状态。启动阶段不产生工具结果；它属于按需业务状态。

关联词：Tool、能力定义、按需业务状态。

### 基础服务

启动时为整个进程提供支撑、但不直接实现业务能力的长期组件集合，例如日志系统和停止控制。

关联词：日志系统、停止控制、长期基础状态。

### 长期基础状态

服务启动后通常持续到进程停止的一组状态，例如运行时配置、插件实例、能力注册表和传输通道。它们为每次请求提供共同基础。

关联词：按需业务状态、生命周期、传输通道。

### 按需业务状态

由具体请求、连接或聊天活动触发创建和更新的短期或可持久化状态，例如协议请求、协议响应、SSE 会话、会话历史和工具结果。

关联词：长期基础状态、协议请求、会话、工具结果。

## 第 2 讲：直接 MCP 请求的一次往返

### JSON-RPC

一种基于 JSON 的远程调用协议约定。本项目用它规定 MCP 请求和响应的基本外形，包括协议版本、请求 ID、方法、参数、结果和错误；MCP 则在此基础上规定工具、资源和提示模板等业务语义。

关联词：JSON、协议请求、协议响应、MCP、请求 ID。

### MCP

Model Context Protocol 的简称，是本项目提供能力给 AI 客户端的业务协议约定。它在 JSON-RPC 的通用请求/响应外壳中定义能力发现、工具调用、资源读取和提示模板获取等动作。

关联词：JSON-RPC、Tool、Resource、Prompt、方法。

### method

协议请求中表示“想执行什么动作”的文本字段。协议层依据它选择相应业务分支；它合法只表示动作被服务器认识，不保证该动作涉及的具体工具、资源或模板一定存在。

关联词：协议请求、路由、方法不存在、参数。

### 路由

根据请求的 method 将结构化协议请求交给对应业务分支的过程。它发生在协议解析之后、插件定位之前。

关联词：method、路由表、协议校验、能力注册表。

### 路由表

服务器内部维护的“method 到业务处理规则”的目录。它只回答协议动作该由哪类处理逻辑承担，不直接保存工具名到插件的对应关系。

关联词：路由、method、能力注册表。

### 协议校验

在进入业务处理前，检查 JSON 文本是否满足 JSON-RPC 基本约定的过程，例如协议版本和 method 的形状是否正确。校验失败时，不应进入注册表或插件。

关联词：JSON-RPC、解析错误、无效请求、协议错误。

### 解析错误

JSON 文本无法被读成结构化数据时产生的协议级错误。此时服务器无法可靠取得 method 或参数，也不会尝试执行任何能力。

关联词：JSON、协议校验、协议错误。

### 无效请求

JSON 可以被读取，但不满足 JSON-RPC 请求基本形状时产生的协议级错误，例如协议版本或必需字段不符合约定。

关联词：协议校验、协议错误、method。

### 方法不存在

请求已经是合法的 JSON-RPC 结构，但其中的 method 不在服务器支持的路由表中。这与解析错误不同：服务器看懂了消息，只是不支持该动作。

关联词：method、路由表、协议错误。

### 协议错误

服务器在解析、校验、路由或内部处理阶段无法按约定完成请求时，放入协议响应 `error` 字段的错误信息。它与插件已执行后的业务失败结果不同。

关联词：协议响应、解析错误、无效请求、方法不存在、内部错误、业务失败。

### 内部错误

服务器已经开始处理请求，但处理过程出现未预期异常时产生的协议错误。它说明调用方不能依赖这次请求得到正常业务结果。

关联词：协议错误、协议响应、业务失败。

### 通知

不携带请求 ID 的合法协议请求。服务器仍解析、路由并执行相应动作，但不创建或发送协议响应，因为客户端没有等待返回值。

关联词：请求 ID、协议请求、协议响应。

### 能力目录

由已登记能力定义组成、返回给客户端的可发现清单。它描述有哪些工具、资源或提示模板可用，不包含每项能力执行后的实时业务结果。

关联词：能力定义、能力注册表、Tool、Resource、Prompt。

### 工具参数

一次 Tool 调用中随工具名提交的业务输入。注册表只依据工具名找到所属插件；具体如何解释和使用参数由该插件负责。

关联词：Tool、工具名、参数、工具结果。

### 业务失败

服务器已成功理解请求、定位到插件并开始执行后，具体业务因条件或外部依赖而失败的结果。例如目标不可访问或输入不满足插件要求。它通常通过结果的失败状态表达，而非表示请求文本无效。

关联词：工具结果、协议错误、插件实例。

### result

协议响应中承载成功处理结果的字段。对于工具调用，它可包含工具结果；对于能力列举，它可包含能力目录。它与 `error` 互斥。

关联词：协议响应、error、工具结果、能力目录。

### error

协议响应中承载协议级失败信息的字段。它用于表达解析、校验、路由或内部处理不能正常完成的情况，与 `result` 互斥。

关联词：协议响应、result、协议错误。

### 序列化

把结构化协议响应转换回可传输 JSON 文本的过程。它是协议主干的出口，之后由不同传输方式负责送给客户端。

关联词：协议响应、JSON、传输通道。

## 第 3 讲：两种传输方式与会话边界

### 字节流

按先后顺序连续到达的一串字节，不天然带有“消息从哪里开始、在哪里结束”的边界。stdio 的标准输入和输出可视为字节流。

关联词：stdio、消息边界、长度头。

### 消息边界

接收方识别一条完整消息起止位置的规则。stdio 依靠长度头定义边界；HTTP 则由一次请求体自然界定边界。

关联词：字节流、长度头、HTTP 请求体。

### 长度头

放在 stdio 消息体之前、声明后续 JSON 文本字节数的信息。接收方读到长度后精确读取对应数量字节，避免把相邻消息混在一起。

关联词：Content-Length、消息边界、stdio。

### Content-Length

长度头使用的字段名，表示紧随其后的消息体占用多少字节。在 stdio MCP 帧中，它用于界定 JSON 文本；HTTP 自身也可使用相似概念界定请求体。

关联词：长度头、JSON、HTTP 请求体。

### MCP 帧

stdio 模式中一次完整传输单元：长度头、空行和指定字节数的 JSON 消息体共同构成一帧。它是传输层外壳，不是 JSON-RPC 请求本身。

关联词：stdio、Content-Length、协议消息、消息边界。

### HTTP 请求体

HTTP 请求中承载实际数据的部分。本项目的 MCP HTTP 入口将其作为完整 JSON-RPC 请求文本交给协议主干。

关联词：HTTP、POST、协议请求、消息边界。

### HTTP POST

客户端向服务器提交数据的 HTTP 方法。本项目用它向消息端点提交 MCP 请求；其即时返回表示 HTTP 投递状态，不等同于 MCP 业务执行结果。

关联词：HTTP 请求体、已接收确认、SSE、会话 ID。

### GET

客户端向服务器获取资源或建立单向事件流的 HTTP 方法。本项目用 GET 建立 SSE 长连接。

关联词：HTTP、SSE、长连接。

### 消息端点

HTTP 模式中接收 MCP JSON 请求的服务地址。客户端在建立 SSE 会话后，携带该会话 ID 向此地址提交 POST 请求。

关联词：HTTP POST、会话 ID、协议请求。

### 已接收确认

HTTP 消息端点对 POST 的即时确认，表示服务器已经接受这次投递。它不包含也不代表 MCP 的最终协议响应或工具执行结果。

关联词：HTTP POST、协议响应、异步。

### 长连接

一次建立后可持续较长时间、允许服务器后续继续发送数据的连接。本项目中 SSE 使用长连接向客户端推送事件。

关联词：SSE、会话、连接断开、重连。

### SSE 会话

HTTP/SSE 传输层为一个客户端连接维护的运行时状态，至少包含会话 ID、待发送消息队列和对应的 SSE 长连接。它的职责是把服务器消息送到正确连接，而不是匹配 JSON-RPC 请求与响应。

关联词：SSE、会话 ID、待发送消息队列、请求 ID。

### 待发送消息队列

属于某个 SSE 会话的有序缓冲区。协议主干产生的 JSON 响应先进入此队列，SSE 发送端再依次将它们推给客户端。

关联词：SSE 会话、异步、生产者、消费者。

### 异步

提交工作与取得最终结果不在同一个立即完成的往返中发生的方式。HTTP 模式下，POST 先得到已接收确认，最终 MCP 响应稍后经 SSE 推送。

关联词：HTTP POST、已接收确认、SSE、待发送消息队列。

### SSE 事件

沿 SSE 长连接发送的一条带事件类型和数据内容的消息。本项目用它传递消息端点信息及最终 JSON-RPC 响应文本。

关联词：SSE、SSE 会话、协议响应。

### 生产者

把数据写入待发送消息队列的一方。在 HTTP MCP 路径中，协议主干完成处理后产生 JSON 响应并将其交给会话队列。

关联词：待发送消息队列、消费者、异步。

### 消费者

从待发送消息队列取出数据并发送到 SSE 长连接的一方。它与生产者配合，将已完成的协议响应交付给客户端。

关联词：待发送消息队列、生产者、SSE。

### 连接断开

客户端或网络导致既有传输连接不再可用的状态。对 stdio，通常意味着输入流结束；对 SSE，客户端可随后尝试携带会话 ID 重连。

关联词：stdio、SSE、重连、会话 ID。

### 重连

客户端在连接断开后重新建立连接的行为。HTTP/SSE 场景中，客户端可携带原会话 ID 尝试恢复将后续事件送往同一会话的能力。

关联词：连接断开、SSE 会话、会话 ID。

## 第 4 讲：插件的契约与三类能力

### 能力契约

主程序与插件之间关于身份、能力发现、结构化输入和统一输出的共同约定。它让主程序无需了解插件内部业务，也能装载、定位和使用插件。

关联词：插件实例、能力定义、统一结果、二进制兼容性。

### 元数据

描述能力而非执行能力本身的数据，例如名称、说明、参数结构、URI 和内容类型。客户端和 LLM 使用元数据发现和理解能力。

关联词：能力定义、能力目录、参数结构、内容类型。

### 参数结构

对一次能力调用可接受哪些字段、字段类型和必填要求的描述。它是调用方构造输入与插件校验业务输入之间的共同依据。

关联词：Tool、工具参数、能力定义、业务校验。

### 内容类型

说明一段资源内容采用何种数据格式的元数据，例如文本或 JSON。客户端据此决定如何解释或展示资源内容。

关联词：Resource、资源内容、元数据。

### 统一结果

不同插件向上层返回的稳定外层数据形状，能承载具体内容和成功或失败状态。统一的是容器和错误语义，不是每个插件的业务文本。

关联词：工具结果、业务失败、协议响应。

### 业务校验

插件在执行前检查业务参数是否满足自身规则的过程。协议层只能确认请求基本形状，不能替代每个插件对路径、范围、权限或领域参数的理解。

关联词：参数结构、工具参数、业务失败。

### 所有权

一个对象由谁负责创建、持续保存和最终销毁的责任关系。在插件系统中，插件实例的生命周期管理与注册表对它的可寻址索引是不同责任。

关联词：插件实例、能力注册表、生命周期、注销。

### 二进制兼容性

主程序和动态插件库在运行时能安全交换对象和数据的兼容条件。它依赖共同的编译和接口契约；不兼容时可能导致装载或跨边界数据传递失败。

关联词：插件库、动态装载、能力契约。

## 第 5 讲：聊天与工具循环

### 聊天请求

前端提交给聊天路径的一次自然语言交互输入，通常包含用户消息，以及可选的会话、历史、模型连接信息和禁用工具列表。

关联词：聊天路径、用户消息、聊天会话、LLM。

### 用户消息

由用户在本轮输入的自然语言内容。服务器将它连同历史、系统消息和工具定义组合进 LLM 上下文。

关联词：聊天请求、消息历史、系统消息、LLM 上下文。

### 消息历史

按时间顺序积累、可发送给 LLM 的消息集合。它可包含系统消息、用户消息、助手消息和 tool 消息；聊天会话历史是其可持久化来源之一。

关联词：会话历史、LLM 上下文、角色、tool 消息。

### 系统消息

在 LLM 上下文中用于设定整体行为、语言、回答风格和工具使用规则的消息。它不是用户输入，也不是工具结果。

关联词：消息历史、角色、LLM 上下文。

### 角色

LLM 消息中标识内容来源或用途的字段，例如系统、用户、助手和工具。角色让模型区分指令、问题、自己的输出和外部工具数据。

关联词：系统消息、用户消息、助手消息、tool 消息。

### 助手消息

代表 LLM 在一轮中生成的文本或提出工具调用意图的消息。模型提出工具后，这条消息会与后续 tool 消息共同成为下一轮上下文。

关联词：LLM、工具调用意图、tool 消息、工具调用 ID。

### LLM 上下文

一次发送给 LLM 的完整输入集合，包括消息历史和可用工具定义。其总量受模型上下文窗口限制。

关联词：消息历史、工具定义、上下文窗口、上下文预算。

### 禁用工具列表

聊天请求中指定、本轮不应提供给 LLM 的工具名称集合。它不删除注册表中的能力，也不阻止其他客户端直接调用这些工具。

关联词：工具定义、LLM 上下文、能力注册表。

### 文本增量

LLM 流式输出中逐段到达的可见文本片段。服务器将其及时转发给聊天前端，实现逐步显示。

关联词：流式输出、聊天事件、完成事件。

### 流式输出

LLM 或服务器不等待完整结果，而是分段持续发送数据的方式。它降低用户等待感，但要求接收方正确处理部分内容、完成标记和错误事件。

关联词：文本增量、SSE、完成事件、错误事件。

### 工具调用意图

LLM 产生的结构化请求，表示它希望服务器执行某项工具。它包含工具调用 ID、工具名和参数文本，但本身不是工具已执行的证明。

关联词：LLM、工具调用 ID、工具参数、工具循环。

### 工具调用 ID

用于关联 LLM 提出的一次工具调用与该调用结果的唯一标识。一个 LLM 返回中有多个工具意图时，ID 防止结果混淆。

关联词：工具调用意图、tool 消息、助手消息。

### tool 消息

写入 LLM 消息历史、承载一次工具执行结果的消息类型。它关联对应工具调用 ID，使模型在下一轮能理解结果来源。

关联词：工具结果、工具调用 ID、消息历史、角色。

### 工具循环

LLM 提出工具意图、服务器执行工具、结果写回 LLM 上下文、再请求 LLM 的重复过程。没有工具意图时该循环立即结束并输出最终文本。

关联词：工具调用意图、工具结果、LLM 上下文、轮数上限。

### 上下文窗口

某个 LLM 一次可接受和处理的上下文最大容量。超过该容量会导致请求失败、截断或需要摘要压缩。

关联词：LLM 上下文、上下文预算、Token。

### 上下文预算

系统为当前模型设定、用于控制消息和工具结果总量的容量估计。它帮助决定何时截断单个结果或压缩历史。

关联词：上下文窗口、Token、截断、摘要压缩。

### Token

LLM 处理文本时使用的近似计量单位，不等同于字符数或汉字数。上下文窗口和上下文预算通常以 Token 衡量。

关联词：上下文窗口、上下文预算、Token 估算。

### Token 估算

在不调用模型分词器时，对文本大约占用多少 Token 的计算。它用于提前控制工具结果和消息历史的大小。

关联词：Token、上下文预算、截断。

### 截断

将过长内容裁剪到允许的上下文预算内的过程。正确做法是保留截断提示，使后续模型和用户知道原始内容并不完整。

关联词：工具结果、上下文预算、截断标记。

### 截断标记

附在截断结果上的说明，表明当前文本不是完整原文，并可携带原始长度或估算容量等信息。

关联词：截断、可观察性。

### 摘要压缩

当总体消息历史过大时，将较早内容提炼为更短摘要并替代原始细节的上下文控制方式。它保留连续性，但可能丢失部分精确原文。

关联词：消息历史、上下文预算、截断。

### 轮数上限

工具循环允许的最大重复次数。达到上限后系统停止继续请求 LLM 或工具，防止无限循环和不可控资源消耗。

关联词：工具循环、错误事件、资源保护。

### 聊天事件

聊天流中传给前端的状态消息，例如文本增量、工具开始、工具结果、完成或错误。它的语义不同于 MCP 的 JSON-RPC 响应。

关联词：流式输出、完成事件、错误事件、SSE。

### 完成事件

聊天流中表示本轮已成功产生最终回答的终止事件。接收方不应把仅收到文本增量误认为完成。

关联词：聊天事件、文本增量、错误事件。

### 错误事件

聊天流中表示本轮无法继续的终止事件，例如 LLM 连接失败、工具循环达到上限或请求无效。它与完成事件互斥。

关联词：聊天事件、完成事件、LLM、轮数上限。

## 第 6 讲：错误、边界与可靠性

### 故障边界

系统中一个阶段能够明确区分“输入尚未被理解”“已定位业务”“已完成但未送达”等状态的位置。按边界分类失败，能决定正确的错误表达和恢复动作。

关联词：传输失败、协议错误、业务失败、可靠性。

### 传输失败

消息因帧不完整、连接断开、会话不存在或发送失败而无法正常进出服务器的情况。它可能发生在协议层之前，或业务完成之后的返回阶段。

关联词：传输通道、连接断开、SSE 会话、协议响应。

### 可靠性

系统在失败、并发、外部依赖和停止过程中仍能保持明确边界、可观察状态和可恢复行为的能力。它不要求永不出错，而要求错误不被悄悄放大或误报为成功。

关联词：故障边界、可观察性、恢复、资源保护。

### 资源保护

通过上下文预算、结果截断、轮数上限、超时或队列策略限制 CPU、内存、连接和等待时间无界增长的措施。

关联词：上下文预算、轮数上限、超时、背压。

### 超时

对外部操作允许等待的最长时间。达到该时间后应返回可诊断失败或执行取消，避免一个慢依赖无限占用资源。

关联词：外部依赖、资源保护、重试。

### 外部依赖

不由当前服务器完全控制的资源或服务，例如网络 API、LLM 服务、文件系统或命令执行环境。它们的失败必须被转换为明确结果。

关联词：插件业务、LLM、超时、重试。

### 可观察性

通过日志、事件、状态和指标了解系统实际运行及失败位置的能力。它应帮助定位问题，同时避免记录不必要的敏感数据。

关联词：日志系统、关联标识、敏感数据。

### 关联标识

用于把跨层事件串成同一条执行链的标识集合，包括请求 ID、SSE 会话 ID、聊天会话 ID和工具调用 ID。

关联词：请求 ID、会话 ID、工具调用 ID、可观察性。

### 敏感数据

不应因日志、错误信息或持久化而随意暴露的数据，例如访问密钥、私有文件内容、命令参数或用户隐私。排障信息应避免不必要地包含它们。

关联词：日志系统、可观察性、持久化。

### 恢复

失败发生后让系统或调用方回到可继续工作状态的动作，例如修正请求、重连、重新获取能力目录、修复外部依赖或按条件重试。

关联词：重试、重连、故障边界。

### 重试

在一次失败后重新执行相同或等价操作的行为。是否安全取决于失败原因和操作是否幂等；不能默认所有 Tool 都可安全重试。

关联词：幂等性、外部依赖、超时。

### 幂等性

同一个操作执行一次或重复多次，产生等价最终效果的性质。具有副作用的 Tool 若不具备幂等性，重试可能产生重复修改或重复外部操作。

关联词：重试、Tool、业务失败。

### 背压

当消费者处理速度低于生产者时，系统限制、缓冲或拒绝新增数据以避免队列和内存无界增长的机制。队列设计和流式连接都需要考虑它。

关联词：待发送消息队列、生产者、消费者、资源保护。

### 线程安全

多个执行线程同时访问共享状态时，仍不发生数据竞争、消息串线或状态破坏的性质。它需要结合数据所有权、同步和生命周期一起保证。

关联词：SSE 会话、对话历史、能力注册表、并发。

### 并发

多个请求、会话或后台任务在时间上交错执行的运行状态。并发本身不是错误，但要求共享状态的读写和清理有明确规则。

关联词：线程安全、待发送消息队列、对话历史。

### 优雅停止

服务器接到停止请求后，有序停止接收新工作、关闭传输、清理索引和释放长期对象的过程。它比直接终止更能避免遗留不一致状态。

关联词：停止控制、生命周期、注销。

### 持久化

将内存中的状态写入持久存储，使其在进程重启后仍可恢复的过程。本项目主要用于聊天会话历史。

关联词：会话历史、恢复、敏感数据。

## 第 7 讲：回到代码验证模型

### 纵向追踪

选择一条具体请求，从入口一直跟到出口的阅读和验证方法。它优先建立跨模块因果关系，再补充局部实现细节。

关联词：数据流、调用链、最小案例。

### 调用链

一次请求在不同运行时角色和边界之间依次经过的处理关系。它强调控制权和数据从谁流向谁，而不是单个模块内部的细节。

关联词：纵向追踪、数据流、边界。

### 最小案例

只包含验证一个行为所需最少输入和依赖的测试或运行场景。它能让观察到的响应、事件或日志更容易归因。

关联词：纵向追踪、黑盒验证、假设。

### 黑盒验证

不依赖内部实现细节，只通过输入和可观察输出确认系统行为是否符合合同的方法。例如提交请求并检查响应、SSE 事件或日志。

关联词：最小案例、行为合同、可观察性。

### 白盒验证

结合内部控制流、状态和数据结构检查系统行为的方法。它适合在已有运行时模型后确认边界是否真的按预期实现。

关联词：纵向追踪、行为合同、代码阅读。

### 行为合同

由协议、测试和已确认运行行为共同构成的稳定承诺，例如合法请求能得到响应、通知不响应、工具名能定位插件。修改实现时应避免无意破坏这些承诺。

关联词：测试、回归测试、黑盒验证。

### 单元测试

隔离验证一个小范围逻辑输入输出的测试类型。它适合固定协议解析、路由和注册表等局部行为。

关联词：测试、集成测试、行为合同。

### 集成测试

验证多个角色或边界组合后是否能完成一条完整路径的测试类型，例如传输、协议和插件能否协同工作。

关联词：测试、单元测试、回归测试、纵向追踪。

### 回归测试

为已确认行为保留的自动化测试，用于防止后续修改再次破坏同一行为合同。

关联词：测试、行为合同、单元测试。

### 假设

根据流程图或已有证据提出、可通过最小案例、日志或代码追踪验证的暂定判断。一次运行观察最好只验证一个假设。

关联词：最小案例、可观察性、结论。

### 证据

用于支持或推翻一个假设的可复查事实，例如响应内容、事件序列、日志记录或测试结果。

关联词：假设、可观察性、结论。

## 第 2 讲源码展开：JSON-RPC 请求主干

### `std::optional`

C++ 中表示“可能有值、也可能无值”的容器类型。本项目用它表示解析失败时没有协议请求，以及正常通知处理后没有协议响应；两种空值的业务语义不同。

关联词：协议请求、协议响应、通知、解析错误。

### Lambda 回调

可在定义处捕获外部状态的匿名函数对象。本项目把统一协议管道定义为回调，再交给不同传输实现，因此 stdio 与 HTTP 入口可以复用同一处理逻辑。

关联词：回调、传输通道、调用链。

### 回调

由一个组件保存、在特定事件发生时由该组件调用的函数。本项目中传输层收到完整 JSON 文本时，调用上层设置的消息回调。

关联词：Lambda 回调、传输通道、协议主干。

### 路由映射

将 method 文本映射到对应处理规则的哈希表。本项目的路由器用它快速选择初始化、能力列举、能力调用等分支。

关联词：路由表、method、哈希表。

### 哈希表

通过键快速查找值的数据结构。本项目用它实现 method 到处理规则、工具名到插件实例等映射；遍历时通常不保证稳定顺序。

关联词：路由映射、能力索引、工具名。

### 异常传播

底层函数不在本地处理错误，而将异常交给调用链上层处理的方式。本项目的路由入口捕获业务处理函数抛出的标准异常，并转为内部协议错误。

关联词：内部错误、协议错误、调用链。

### 默认参数回退

从 JSON 读取字段时，字段缺失就使用预设默认值的行为。本项目工具调用参数缺少工具名时会得到空字符串，随后在能力查找阶段失败。

关联词：工具参数、内部错误、业务校验。

### 序列化方法

将某个 C++ 数据对象转换成 JSON 值的方法。协议请求处理完成后，能力定义、业务结果和协议响应都会通过各自的序列化方法形成可传输 JSON。

关联词：序列化、JSON、统一结果。

## 第 3 讲源码展开：stdio 与 HTTP+SSE

### 纯虚接口

C++ 中只声明行为、不提供具体实现的抽象接口。本项目的传输接口规定启动、停止、发送和设置回调四种行为，stdio 与 HTTP+SSE 分别实现它。

关联词：传输通道、多态、回调。

### 多态

调用方通过同一抽象类型使用不同具体实现的能力。本项目的协议主干只调用传输接口的 `send`，实际写 stdout 还是推 SSE 由具体对象决定。

关联词：纯虚接口、传输通道、调用链。

### 读线程

负责持续从输入来源读取数据的执行线程。stdio 模式将读取循环放在单独线程中，而启动调用会等待该线程结束。

关联词：线程、stdio、EOF。

### 原子标记

可被多个线程安全读取和写入的简单状态值。本项目用运行标记协调读取循环、SSE 发送循环和停止操作。

关联词：线程安全、优雅停止、条件变量。

### 互斥锁

保证同一时刻只有一个执行者访问某段共享状态的同步工具。本项目用它保护 stdout 写入、会话 map、会话队列和当前会话字符串。

关联词：线程安全、共享状态、条件变量。

### 条件变量

让一个线程在条件未满足时等待、由另一个线程在状态改变后唤醒的同步工具。本项目的 SSE 消费者在队列为空时等待，生产者入队后通知它。

关联词：待发送消息队列、生产者、消费者、互斥锁。

### EOF

End Of File 的简称，表示输入流已结束。stdio 读取循环遇到 EOF 后会停止运行，不再等待新的 MCP 帧。

关联词：stdio、读线程、连接断开。

### 线程局部存储

每个线程各自拥有一份变量值的存储方式，不与其他线程共享。当前 HTTP 实现的“当前会话”注释声称采用这种思路，但实际字段是共享字符串；二者不能混同。

关联词：当前会话、互斥锁、并发、会话串线。

### 当前会话

HTTP MCP 请求处理期间，用于决定 `send` 应把响应放入哪个 SSE 队列的会话上下文。当前实现把它存为 transport 对象的共享字符串，而非请求对象的显式字段。

关联词：会话 ID、待发送消息队列、会话串线。

### 会话串线

并发请求下，一个会话的响应被错误投入另一个会话队列的故障。共享“当前会话”若未绑定到请求或线程，就可能出现这种问题。

关联词：当前会话、并发、线程局部存储、SSE 会话。

### Content Provider

HTTP 库提供的持续写入响应内容的回调机制。本项目用它维持 SSE 长连接，并从待发送消息队列持续取出 JSON 响应写给客户端。

关联词：SSE、长连接、消费者、条件变量。

### HTTP 状态码 202

表示服务器已接受请求但尚未完成处理的 HTTP 状态。本项目的 `/message` 使用它确认 POST 已投递；最终 MCP 结果仍需从 SSE 流读取。

关联词：HTTP POST、已接收确认、SSE、协议响应。

### 显式上下文传递

将会话 ID 等请求归属信息作为函数参数或请求对象的一部分沿调用链传递，而不是从共享可变状态读取的设计方式。它可避免并发时当前会话被覆盖。

关联词：当前会话、会话串线、调用链。
